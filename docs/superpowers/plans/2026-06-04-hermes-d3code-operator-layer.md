# Hermes D3Code Operator Layer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Hermes the memory, orchestration, and continuous-learning layer around D3Code while keeping D3Code the Rocket D3-native execution, safety, and modernization harness.

**Architecture:** D3Code remains the domain engine for Rocket D3 profiles, TCL, BASIC, dictionaries, evidence, and migration outputs. Hermes/ECC patterns are imported selectively as an operator layer: durable memory, skill evolution, multi-session orchestration, evals, and run learning. System Builder and Rocket D3 reference manuals become indexed first-class knowledge sources used by D3Code tools and skills.

**Tech Stack:** TypeScript/Node 20, existing D3Code CLI/TUI, Markdown skills and plans, JSON manifests, existing D3Code reference ingestion, ECC/Hermes source material from `/Users/paul/development/TENSOLOGY/DECISIONS/COMPETITION/ecc`.

## Design Principles

- D3Code is the D3 execution authority.
- Hermes is memory, coordination, and learning.
- ECC is a source of patterns, not a dependency to dump into the repo.
- Manuals are evidence sources, not prompt stuffing.
- Skills are loaded on demand and must be D3-specific after import.
- No private paths, customer names, credentials, or local-only Hermes state are committed.

### Task 1: Write the Architecture Boundary

**Files:**
- Create: `docs/architecture/hermes-d3code-operator-layer.md`

- [ ] **Step 1: Create the architecture document**

Write:

```markdown
# Hermes D3Code Operator Layer

## Boundary

D3Code owns Rocket D3 execution:

- connection profiles
- account inspection
- TCL execution safety
- BASIC parsing and linting
- dictionary and data-shape capture
- modernization evidence
- generated app/API artifacts

Hermes owns operator memory and coordination:

- durable lessons from sessions
- multi-session orchestration
- recurring workflow promotion into skills
- reference routing policy
- quality/eval loops
- handoff summaries

ECC is an upstream pattern source. Its skills and harness ideas may be adapted into D3Code only when they improve D3-specific outcomes.

## Non-Goals

- Do not vendor the whole ECC repo into D3Code.
- Do not make D3Code a generic agent framework.
- Do not store private Hermes state in Git.
- Do not bypass D3Code safety gates through Hermes orchestration.

## First-Class Knowledge Sources

- Rocket D3 reference manual
- Rocket D3 user guide
- Rocket MV BASIC reference material
- System Builder reference manuals
- Crystal Logic operator notes
- Verified session memories generated by D3Code

## Operating Model

Hermes asks D3Code to do D3 work. D3Code returns structured evidence. Hermes stores durable lessons only after verification.
```
